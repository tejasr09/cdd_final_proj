## Facilitator opening

> We are testing the design, not you. Please think aloud if comfortable. You may skip a task or stop at any time. This is a prototype using synthetic information; no real records are needed. We will take notes, and will not record unless you separately agree. Is it okay to continue?

## Scenario

Use the synthetic “Advanced Computing Laboratory unavailable” example from Appendix C. Clearly state it is illustrative and does not describe real campus data. Do not imply the prototype's scores are validated predictions.

## Tasks

1. Create an event with a start time and severity, then associate a trigger entity.
2. Find or add a dependency and confirm its direction from source to target.
3. Configure and run an analysis; identify whether the displayed result is an estimate or a probability.
4. Inspect one result and explain what its path and confidence label mean.
5. Create a hypothetical scenario intervention and compare it with the baseline.
6. Identify what changed and confirm whether live data was modified.

For each task, record completion, observable errors, help requested, and participant comments. Do not coach unless necessary for safety or the session protocol.

## Debrief

- What was unclear or surprising?
- What information was missing?
- What would you change first?
- Did any wording imply certainty that was not intended?
- Did the graph have an understandable non-canvas alternative?
- Anything else the participant wants the team to know?

## Analysis discipline

- Keep observations separate from interpretations and design decisions.
- Record participant count and recruitment method only after the sessions occur.
- Do not report completion rates or averages from an incomplete sample without describing the method and denominator.
- Do not create a SUS score unless the team actually administered the instrument using its defined method.
- Record contradictory findings and limitations.
- Link each proposed design change to evidence; mark untested changes as hypotheses.
