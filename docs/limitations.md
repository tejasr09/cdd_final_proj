# Limitations and Future Work

Updated: 2026-11-14

This list reflects the evidence available for the local Phase 11 review. It is
not a claim that the system is ready for production.

## Release blockers and outstanding human evidence

- **Production identity and ingress:** the app's local identity adapter is
  development-only. A production identity provider, session lifecycle, TLS
  ingress, and security review are not implemented. Keep public ingress
  disabled.
- **Cloud deployment:** Phase 9 remains partial. No ACR image push, ACI
  deployment, Azure health verification, cost approval, rollback, or cleanup
  evidence exists.
- **Remote CI:** no PR or GitHub Actions run was triggered for
  `feature/phase11-release-hardening`; remote Git operations were not
  authorized.
- **Human UX evidence:** interviews, participant consent, validated findings,
  a human-owned Figma prototype, and task-based usability results remain
  TODO(human). Personas and synthetic tasks are hypotheses, not research.
- **Release sign-off:** human release-candidate approval has not been given.

## Security, data, and operations

- Local authentication uses synthetic development identities and must not be
  used as production authentication.
- A live PostgreSQL analysis and a cross-organization 404 check passed, but
  production PostgreSQL configuration, concurrency behavior, and
  tenant-isolation stress tests remain unverified.
- Dependency audits reported no findings in the checked lockfiles, and Trivy
  reported no image vulnerabilities. Current Trivy secret-scanner summaries
  rendered `-`; treat secret-scan coverage as inconclusive rather than claiming
  a zero-secret result.
- Local Compose backup/restore guidance was exercised against a disposable
  database. This is not a production backup policy; production retention,
  encryption, off-site storage, recovery objectives, and restore drills need
  separate design and approval.
- Audit events are generated by application operations and covered by tests;
  database-level append-only enforcement is not implemented.

## Analysis and performance

- Impact scores are heuristic estimates, not probabilities or guaranteed
  outcomes. Confidence describes dependency review quality, not likelihood.
- Traversal is bounded and reports when limits are reached. A local
  120-node/7,140-edge synthetic DAG reached the 10,000-path cap; larger or
  denser graphs may return explicitly incomplete results.
- A local three-run benchmark measured a 5,000-node chain median of
  0.875799 seconds and the capped DAG median of 3.346820 seconds. These
  workstation-specific measurements are not benchmarks across hardware and
  are not SLOs.
- Analysis is synchronous; production-scale workload, queueing, concurrent
  writes, and latency under load have not been assessed.

## Future work

1. Select and implement a production identity provider and TLS ingress before
   enabling public access.
2. Obtain human UX evidence and record actual findings without treating
   hypotheses as validated.
3. Authorize and complete PR CI and human-operated ACR/ACI deployment,
   including immutable image digests, cost review, health, rollback, and
   cleanup evidence.
4. Define production PostgreSQL concurrency, backup retention, encryption,
   restore objectives, and audit-log immutability requirements.
5. Add representative, repeatable performance baselines and scale tests; keep
   traversal limits visible to users.
6. Conduct human accessibility and usability reviews, including
   screen-reader behavior.
